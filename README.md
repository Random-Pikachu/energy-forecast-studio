# Energy Forecast Studio

A local React dashboard for the BTP building-load forecasting models. The interface uses React, Tailwind CSS, Lucide icons, and a lightweight SVG chart. A small Python API serves the built page and runs PyTorch inference. No separate model-hosting service is needed for the college demo.

The dataset and model checkpoints from the [project Drive folder](https://drive.google.com/drive/folders/1aXdBI0_tYRyTDYVA34PzWXCkWm6dI1FY) are included locally, so predictions do not contact Google Drive.

## Run on this machine

You need `uv`, Node.js, npm, and internet for the first dependency installation. Use two short setup steps, then one command to run the app:

```bash
cd ~/Documents/projects/IOTBDM
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
cd frontend && npm install && npm run build && cd ..
.venv/bin/python server.py
```

Open **http://127.0.0.1:8000**. Press `Ctrl+C` to stop the server. After the first setup, only the last command is needed. Rebuild with `cd frontend && npm run build` after changing React files.

For frontend development, run `.venv/bin/python server.py` in one terminal and `cd frontend && npm run dev` in another. Vite proxies `/api` to the Python server; use the URL printed by Vite.

## Use the dashboard

1. Choose CNN–Transformer, CNN–GRU, or CNN–LSTM and a trained lookback/horizon combination.
2. Under **Source**, choose **History** and a date/hour, including 2018; **Enter values** to paste or type your own readings and set when they start; or **Upload CSV** with `timestamp,building_power` columns. A model with a 168-hour lookback needs 168 consecutive hourly readings.
3. Click **Generate forecast**. The chart shows past readings, forecast values, and actual future readings when replaying history. The result table can be exported as CSV.

Historical readings can be edited before running a forecast. The earliest selectable hour depends on the lookback: July 1, 2018 at 07:00 for an 8-hour model, and July 7 at 23:00 for a 168-hour model. Errors on training-period dates are illustrative and are not held-out test scores.

## Data and checkpoints

- `data/building_multivariate.csv`: 11,486 continuous hourly rows from July 2018 to October 2019.
- `data/scalers.json`: training-split scaler statistics used for inference.
- `models/catalog.json`: all 80 downloaded checkpoints, with Drive IDs and model configurations. 74 have a compatible output shape. Six older CNN–LSTM files are labeled as multi-hour models but contain a one-output head, so the dashboard hides them.
- `app/architectures.py` and `app/forecast.py`: reconstructed model classes, validation, and inference.
- `server.py`: local JSON API and static file server.
- `frontend/`: React interface. `frontend/dist/` is generated by `npm run build`.

The Transformer and LSTM preprocessing follows the original notebooks: `building_power`, `hour`, and `day_of_week` in that order, scaled using statistics from the first 70% of the chronologically sorted dataset. The CNN–GRU folder has no original training script or scaler metadata; the app loads its checkpoints with their recovered architecture and uses the same input scaling. CNN–GRU predictions can differ from the old saved result CSV.

The dashboard displays building power/load in the dataset's units. It does not convert the values to energy units.

## Memory use and checks

PyTorch is imported only on the first forecast. Inference runs on CPU with gradients disabled, two CPU threads, and a one-model cache. The API reads only the selected model checkpoint. A sequential check of all 74 usable configurations with the CPU-only PyTorch wheel peaked at about **326 MB RSS** in this environment.

Run the model check with:

```bash
.venv/bin/python scripts/check_models.py
```

The API exposes `GET /api/catalog`, `GET /api/history?modelId=...&at=...`, and `POST /api/forecast`. It accepts local historical replay or a CSV upload (2 MB maximum).
